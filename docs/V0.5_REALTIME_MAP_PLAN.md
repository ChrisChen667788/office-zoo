# v0.5.0+ · 实时地图 / 房间道具 / 玩家可交互

> 用户原话:**"经典模式的角色们移动需要实时渲染的,而不是目前这种跳帧动画的模式,行动的要更流畅,每个房间要有适合该房间的家具、内饰和道具,玩家可以使用道具,增加趣味性"**

把这个目标拆成 3 个 PR,每个独立可发布、可观测。

---

## 现状 (v0.4.0)

- 服务端 `runFreeRoam()` 是 **6 ticks × 1.5s** 离散循环
  - 每 tick 30% 概率一个玩家发起 commute
  - `pathProgress` 一次跳 0.34
  - 每 tick `emit('tick', { players, tickAt })`
- 客户端 `GameMap.tsx` 用 `requestAnimationFrame` 60fps lerp 收到的快照
  - 房间间用 Catmull-Rom 走弧
  - 当前发言者头像 1.18× + 房间脉冲

**问题:**
1. **离散感** — 玩家 1.5s 才更新一次目标,lerp 中间是预估,不是真实位置
2. **房间是空的** — 只有名字标签,没有家具/道具/可交互物件
3. **玩家不能用道具** — 没有道具系统,纯 NPC 演剧

---

## v0.5.0 · 实时位置 (4-6 周)

### 服务端
- `tick` 频率从 1.5s 提到 **250ms**(4 Hz),仍然 emit `'tick'`
  - 每个玩家 commit `velocity (vx, vy)`,服务端纯 number 计算位置
  - `pathProgress` 改成连续 `0..1` 浮点,每 tick 推进 `velocity * dt`
  - "瞎晃" 行为:玩家在房间内有自己的 in-room 微目标(沙发/咖啡机/桌子),不是固定坐房间中心
- 新增 `Vec2 = { x: number; y: number }` —— position 用真坐标,而非"房间中心+grid offset"
- 服务端只发 `velocity + checkpoint position`,客户端做 dead-reckoning(Quake 风格)
  - payload 体积:9 玩家 × 24B/玩家 × 4 Hz ≈ 864 B/s,完全可承受
  - 网络延迟 < 200ms 时,客户端预测和服务端权威几乎一致

### 客户端
- `GameMap.tsx` 用 dead-reckoning 而不是 lerp
  - 每帧 `pos += velocity * dt`(本地推进)
  - 收到 server tick → 计算位置偏差,3 帧内插值校正
- 走廊路径用 **A\* 寻路**,而不是固定预设走廊(允许玩家斜穿房间)
- 添加"足迹"粒子效果(玩家走过留 0.5s 的尘土)

### 验收
- 玩家移动看起来"流畅,无跳帧"
- 网络抖动 ±200ms 时不出现回弹
- 9 玩家全场移动,客户端 < 16ms/帧(60fps)

## v0.6.0 · 房间家具 / 道具 (3 周)

### 数据模型(shared)
```ts
export interface RoomFurniture {
  id: string;
  roomId: string;
  type:
    | 'desk' | 'chair' | 'sofa' | 'whiteboard' | 'projector'
    | 'coffee_machine' | 'fridge' | 'water_dispenser' | 'snack_table'
    | 'server_rack' | 'cctv' | 'printer' | 'water_cooler' | 'fish_tank'
    | 'bed' | 'plant' | 'noticeboard';
  /** 局部坐标 (相对房间左上),不是全局坐标 */
  pos: Vec2;
  /** 占地宽高,玩家走路要绕开 */
  size: Vec2;
  /** 是否可交互 */
  interactable: boolean;
  /** 交互类型 — 决定玩家用了之后发生什么 */
  action?: 'sit' | 'use' | 'inspect' | 'eat' | 'drink' | 'print' | 'recharge';
  /** 视觉:Minimax 生成的 isometric 家具图(放 packages/server/public/furniture/) */
  spriteKey: string;
}

/** 每个房间预设家具列表 */
export const ROOM_FURNITURE: Record<string, RoomFurniture[]> = {
  茶水间:    [...咖啡机/水冷器/零食桌/冰箱],
  会议室:    [...大长桌/座椅×8/白板/投影],
  HR办公室:  [...HR桌/客椅/文件柜/标语板],
  服务器机房:[...4 个 server rack / CCTV],
  老板办公室:[...大办公桌/真皮沙发/吊兰/鱼缸],
  开放工区:  [...8 个工位 desk + chair/打印机/绿植],
  // ...10 个房间各 4-8 件家具
};
```

### 服务端
- 新增 `services/furnitureGen.ts` — 复用 `iconGen` 的 model chain,batch 生成 ~80 件家具贴图
  - prompt:"isometric pixel-art office X, transparent bg, 256×256"
  - 缓存到 `packages/server/public/furniture/<key>.png`
- 启动时一次性 background generate 所有缺失的家具贴图
- 玩家移动算法新增 collision avoidance —— 玩家路径要绕开 furniture footprint

### 客户端
- `GameMap.tsx` 在画 room 之后画 furniture (按 isometric Y 排序)
- 玩家走到家具旁边时:屏幕上方弹小 tooltip "按 [E] 使用咖啡机"(预留人工玩家交互入口)
- 当 NPC AI 选择"去喝咖啡"时,GameMap 显示玩家头像 + "喝咖啡" emoji 浮上头顶

### Activity 系统升级
原来的 6 种 activity (`idle/work/chat/sneak/meeting/commute`) 升级:
- 每个 activity 绑定一件 **目标家具**
- `work` → 走到自己的 desk + 坐下(`action: 'sit'`)
- `coffee` → 走到 coffee_machine + 用(`action: 'drink'`)
- `print_evidence` → 服务器机房 / 文印室,走到 printer + 打印(`action: 'print'`)
- 这样移动 + 行为有了真实的"motivation",而不是凭空切换活动

### 验收
- 进入沉浸/经典模式,每个房间能看到 4-8 件 isometric 家具
- AI NPC 自主使用家具,头顶浮现 emoji 描述(☕ / 💻 / 🖨️)
- 单局至少 3 次"NPC 用道具"的可见行为

## v0.7.0 · 真人玩家可使用道具 (4 周)

### 道具系统
新增 `Item` 概念 —— 玩家手上的可携带物件:

```ts
export type ItemKind =
  | 'coffee'     // 喝了下一轮发言更激进 (+10% 攻击词频率)
  | 'evidence'   // 打印了某玩家的"证据"  能在投票阶段多得 1 票
  | 'chat_log'   // CCTV 录像  显示"昨晚 X 在 Y 房间"
  | 'snack'      // 零食 — 路过零食桌捡到,吃了恢复一格"班味"
  | 'flash_drive' // 服务器机房 — 偷取数据,可揭穿 dog 阵营 1 名
  | 'name_card'   // 名片 — 收集 5 张拼成"老板小红书",触发结局彩蛋
  | 'lawyer_card' // 法务顾问留下的 — 投票阶段使用 = 复议
;

export interface PlayerInventory {
  playerId: string;
  items: { kind: ItemKind; pickedUpAt: number; usedAt?: number }[];
}
```

### 服务端
- AI NPC 行为升级:idle 时不仅"走 + 喝咖啡",还会"路过咖啡机捡 coffee item / 路过文印室拿 evidence"
- 每个回合开始时随机刷新 2-3 件物件在房间里
- 物件被使用时触发对应 effect(影响 prompt / 投票权重 / 揭秘等)

### 客户端
- `Inventory.tsx` 浮动面板 —— 显示当前真人玩家(v0.6 真人模式才启用)持有的物件
- 走到物件旁边 + 按 `E` 拾取 → 物件 fly to inventory 动画
- 在合适场景按数字键 `1-5` 使用某物件
- AI NPC 拾取/使用时:头顶弹 floating "📋 拿到了 X" 字样

### 解锁 Tier (轻 RPG 化)
玩家积累 5 / 10 / 20 / 50 局 → 解锁特殊物件套装(`master_lawyer_kit` / `whistleblower_kit`),给重玩动力。

### 验收
- 真人模式下能拾取 + 使用道具
- AI 也能用道具(看得见效果)
- 30 天用户调研:"玩家觉得道具好玩"≥ 65%

## 工程性: 道具 / 家具 资产管线

```
packages/server/src/services/
├── iconGen.ts        UI icons (modes / personalities / activity)
├── imageGen.ts       角色 23 个 anime 立绘
├── furnitureGen.ts   v0.6.0 — 80+ 件家具 isometric (我们补)
├── itemGen.ts        v0.7.0 — 物件 inventory icon (我们补)
└── tts.ts / llm.ts ...
```

- 全部走 `minimax:image-01` (我们当前能用的) 主链
- 每张图 < 200 KB,一次性 batch 生成,本地缓存
- prompt 风格统一 "transparent bg, isometric, pixel-art chunky" 保证视觉一致

## 性能预算

| 指标 | 当前 (v0.4) | v0.5 目标 | v0.7 目标 |
|---|---|---|---|
| `tick` 频率 | 1.5s | 250ms | 250ms |
| socket 带宽 | ~1KB/min | ~50KB/min | ~80KB/min |
| 客户端 fps | 30 | 60 | 60 |
| canvas draw cost | 1.5ms/帧 | 4ms/帧 | 8ms/帧 (含家具) |
| 服务端 CPU/局 | < 1% | < 3% | < 5% |

---

## 风险 + 对冲

| 风险 | 概率 | 对冲 |
|---|---|---|
| 4Hz tick 网络压力大 | 低 | dead-reckoning,1Hz 校验 |
| 家具图片生成 80+ 张需 ~20 分钟首次 | 高 | 后台 lazy 生成,首次玩看到 emoji 占位 |
| 道具系统让"看戏"模式变复杂 | 中 | 道具默认对真人玩家可见,纯 NPC 局保持简洁 |
| 60fps + 家具 + 9 player 在低端 Android 卡 | 中 | 加 `prefers-reduced-motion` 降级,降 30fps |
