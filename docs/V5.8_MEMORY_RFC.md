## 1. 为什么做这件事

| 痛点 | 现状 | 期望 |
|---|---|---|
| AI 跨局完全无记忆 | 每局 fresh prompt + sanitized 角色,人格漂移大,救过的"恩人"下一局照投不误 | 同一个 archetype 的 AI 在不同 game 里见到同一个 player,带着前情记忆出场 |
| 单局内只有线性 prompt context | 当前 `BaseAgent.generateSpeech` 把全部 `priorSpeeches` 塞进 prompt,8 个人 5 轮就爆 token | episodic memory + retrieval by relevance×recency×importance |
| 没有"高层信念" | LLM 每次都从头推理"谁是狗",同样的事实可能给出矛盾的结论 | 每 5 轮触发 reflection,把 events → 3-5 条 high-level beliefs,下一轮 prompt 注入 |
| 与 Smallville/AI Town 的技术 gap | 我们目前完全 stateless prompt, 是 ITERATION_PLAN 列的"最大技术 gap" | 闭合 gap,技术博客发出去带二次发酵 |

**度量(从 ITERATION_PLAN §B 抄):**
- 同一 AI 在多局表现 **角色一致性 ≥ 90%**(漂移 < 10%)
- 用户调研"AI 像有记忆吗" 满意度 **≥ 70%**
- 技术博客 "用 pgvector + Minimax embedding 给 AI 加记忆 — Smallville 简化版" 二次发酵

## 2. 决策已固化(2026-05-22 钦定)

| 决策项 | 选定 | 否决项 | 否决理由 |
|---|---|---|---|
| **向量存储** | **pgvector** (Postgres extension) | sqlite-vec | sqlite-vec wasm 在 Node 端体验糙;pgvector 生态成熟,Supabase/Neon 免费 tier 直出 |
| | | LibSQL | 走 Turso 锁链路;pgvector 中立 |
| **embedding 模型** | **OpenAI text-embedding-3-small (1536 dim) via Qingyun** | Minimax embo-01 (1024 dim) | 三重证据(见 §5.2)证实 Minimax 已从官方 model lineup 下架 embedding;端点存在但任何 model 名都返回 `1008 insufficient balance` |
| | | 本地 bge-small (ONNX) | Node 端 ONNX 启动慢 + Node-gyp 编译麻烦,不值这点钱省 |
| | | 直营 OpenAI text-embedding-3-small | Qingyun 中转价 ≈ 70-90% 直营价, 同 key 已经在跑 chat, 零基础设施变更 |
| **首发 agent 类型** | **经典模式 7 角色** (`BaseAgent` 在 `agents/BaseAgent.ts`) | 裁了么 HR | 已经有 v0.8.2 `memoryStore.ts` 简版记忆,upgrade 心智负担小;但经典 7 角色是核心模式,memory 价值最大 |
| | | 攒局 squad 成员 | director-driven,prompt 已经够长,加 memory ROI 低 |
| **跨用户 memory boundary** | **chunky-style 同事记仇** | fresh-start "每局新人格" | 你拍板的是 spicy 版,跟产品定位"打工人 catharsis infrastructure" 一致——"那个 AI 又来了, 跟我有过节" 是病毒话题 |

## 3. 架构概览

### 3.1 数据流

```
┌───────────── 单局 game 内 ────────────────────────────────────┐
│                                                              │
│  player speech / vote / round-end                            │
│       │                                                      │
│       ▼                                                      │
│  ┌──────────────────┐    每事件        ┌─────────────────┐  │
│  │  GameEngine      │───────────────▶ │ MemoryWriter    │  │
│  └──────────────────┘                  └────────┬────────┘  │
│       │                                          │           │
│       │ 每 5 轮触发 reflection                    │           │
│       ▼                                          ▼           │
│  ┌──────────────────┐                  ┌─────────────────┐  │
│  │  Reflection LLM  │───────────────▶ │   pgvector      │  │
│  └──────────────────┘   写 belief      │   memory_entries│  │
│       │                                │   table         │  │
│       │ 下一轮 speech prompt              └────────┬────────┘  │
│       ▼                                          │           │
│  ┌──────────────────┐    recall(k=5)             │           │
│  │  BaseAgent       │◀─────────────────────────┘           │
│  │  .recallMemories │                                       │
│  └──────────────────┘                                       │
└──────────────────────────────────────────────────────────────┘
                                          ▲
                                          │ 同一 agent_archetype × 同一 player_user_id
                                          │ 跨 game_id 持久化 (chunky-style)
                                          │
┌─────── 跨 game 持久化 ────────────────────┘
│ 同 player 下次进新局 → 同 archetype agent 自动拉到上局记忆
│ 例: 上局你帮 sass-master 同学说话, 这局 sass-master 主动不投你
└───────────────────────────────────────────
```

### 3.2 数据模型(pgvector schema)

```sql
-- v5.8.0
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE memory_entries (
  id              BIGSERIAL PRIMARY KEY,
  -- agent 身份 (chunky-style 关键 — 不是 by-game)
  agent_archetype TEXT NOT NULL,         -- 'sass-master' | 'social-cat' | ...
  -- target 关系键 — 跟谁有关系
  target_user_id  TEXT,                  -- player 的 X-User-Id, NULL = 通用记忆
  target_player_id TEXT,                 -- in-game player_0..7 id, NULL = 跨局
  -- 来源
  source_game_id  TEXT,                  -- 哪个 game 产生的, NULL = reflection 衍生
  source_round    INT,
  ts              TIMESTAMPTZ DEFAULT NOW(),
  -- 内容
  kind            TEXT NOT NULL,         -- 'event' | 'belief' | 'relationship'
  content         TEXT NOT NULL,         -- 自然语言: "我在第3轮看到张三投了我"
  embedding       VECTOR(1536),          -- OpenAI text-embedding-3-small dim
                                          -- NULL 允许 (§5.6 fallback): embedding 失败时
                                          -- recall 走 LIKE 全文检索
  -- recall 排序权重
  importance      REAL DEFAULT 0.5,      -- 0-1, LLM 自评 / 启发式
  decay_ts        TIMESTAMPTZ            -- recency 计算锚点 (= ts 默认)
);

-- 加速 recall by (agent, target, kind)
CREATE INDEX idx_mem_agent_target ON memory_entries (agent_archetype, target_user_id, kind);

-- HNSW 向量索引 — 1024 维 Minimax, m=16, ef_construction=64
CREATE INDEX idx_mem_embedding ON memory_entries
  USING hnsw (embedding vector_cosine_ops);
```

**Schema 设计要点:**
- `target_user_id` 是 **chunky-style 的灵魂键** — 这就是"我对这个人的记忆"。NULL 表示"我对 game 的通用印象"
- `(agent_archetype, target_user_id)` 复合索引覆盖 95% 的 recall query
- `embedding` 走 cosine 距离 + HNSW 索引,1536 维匹配 OpenAI text-embedding-3-small
- `kind` 三类 event/belief/relationship 跟 Smallville 论文对齐

### 3.4 BaseAgent diff 形状(伪 code)

```ts
// 当前 (v5.7.0):
async generateSpeech(context, priorSpeeches?) {
  return callLLM({ system, prompt: `当前职场状况: ${context}` });
}

// v5.8.0:
async generateSpeech(context, priorSpeeches?, opts?: { memoryRecallQuery?: string }) {
  const recalled = await memoryRecall.search({
    agentArchetype: this.archetypeId,
    targetUserId: opts?.targetUserId,   // 当前 round 的 "我对谁说话" 主体
    query: opts?.memoryRecallQuery ?? context,
    k: 5,
    // 权重: relevance * 0.5 + recency * 0.3 + importance * 0.2
  });
  const memoryBlock = recalled.length
    ? `\n\n【你的相关记忆】\n${recalled.map(m => `- ${m.content}`).join('\n')}\n`
    : '';
  return callLLM({ system, prompt: `${context}${memoryBlock}` });
}
```

## 4. 三轮交付计划

### 4.1 v5.8.0 — pgvector PoC + 单 agent recall(估 20-30 hr)

**目标:** 跑通 "1 个 sass-master agent 跨 2 局对同一个 player 表现出记忆"。

切片:
1. **infra**: docker-compose 起一个本地 pgvector(镜像 `pgvector/pgvector:pg16`),package.json 加 `db:up` script
2. `pgvectorClient.ts` — 单例 pool, 启动时 ensure extension + schema
3. `memoryEmbedder.ts` — Minimax embedding-01 调用 + LRU 缓存(同 content 不重复请求)
4. `memoryWrite.ts` — `writeEvent({agent, targetUid, content, source})` fire-and-forget
5. `memoryRecall.ts` — `search({agent, targetUid, query, k=5})` 返回排好序的 entries
6. `BaseAgent.generateSpeech` 改造: 接受 `targetUserId`, recall 后注入到 prompt
7. socketHandler round-end hook: 把"@张三投了 @李四 出局" 这类事件写成 event memory
8. **手动验证脚本**: `scripts/test-memory-cross-game.ts` — 起 2 局, 第 2 局观察 prompt 中是否含上局记忆

**done-when:** 同一 player 在两局连续 fired-mode 中,第二局开局的 sass-master 第一句话能提到"上次那个 ..."

### 4.2 v5.9.0 — Reflection 层(估 25-35 hr)

**目标:** 每 5 轮触发反思, episodic events → 3-5 条 belief, 注入下轮 prompt。

切片:
1. `reflectionLoop.ts` — 每个 agent 维护 `eventsSinceReflection` 计数器, 触发条件: round % 5 == 0 || eventsSinceReflection > 10
2. Reflection LLM prompt: "你刚刚目击了以下 N 件事..., 总结出 3-5 条关于场上局势的高层判断"
3. 写回 `kind='belief'`, importance 默认 0.7(高于 event)
4. recall 时 belief 优先级 *= 1.5(让 reflection 衍生的判断比原始 events 更容易被取到)
5. UI: HighlightReel 新增 "🧠 AI 心理活动" panel — 展示某 agent 当前 top 3 beliefs(预留 v6.0 完整实现, v5.9 只 expose API)

**done-when:** 同一 game 第 6 轮起, agent prompt 含"你现在相信..." 段, log 显示 beliefs 与实际投票一致性 ≥ 70%

### 4.3 v6.0.0 — 跨局持久 + UI 展示 + 调研(估 30-40 hr)

**目标:** 公开 v6.0.0 — 用户能感知 AI 有记忆。

切片:
1. memory 跨 `game_id` 持久化 cap 策略(每 agent×player 最多 200 entries, LRU 由 importance × recency 计分驱逐)
2. HighlightReel "🧠 AI 心理活动" 完整面板 — 展示某 agent top 5 beliefs + 最近 10 events
3. Landing 加 "💭 你的 AI 同事" 入口 — 列出对当前 user 有 memory 的 agents + 关系简评
4. 调研问卷接入 — 玩完游戏弹"AI 像有记忆吗?" 5 档评分
5. 写一篇 `docs/V6_MEMORY_TECH_BLOG.md`(中文 + 英文), 投 HN / 掘金 / V2EX
6. **v6.0.0 release notes + screenshot 三连**

**done-when:** 满足 ITERATION_PLAN §B 的 3 个度量指标

## 5. 执行细节决策(全部 ✅ 确认 — 2026-05-22)

| # | 问题 | ✅ 决定 | 备注 |
|---|---|---|---|
| **5.1** | pgvector 部署目标(prod) | **Neon 免费 tier (3 GB)** | pgvector 一等公民, 连接池托管, 容量比 Supabase 大 5× |
| **5.2** | embedding 模型(原本是 Minimax 端点确认) | **OpenAI text-embedding-3-small via Qingyun (1536 dim)** | 三重证据(下文)证实 Minimax 已下架 embedding,直接 pivot |
| **5.3** | 同 user 多浏览器/设备的 memory 合并 | **不合并 — userId 完全独立** | 跟 v1.3.0 quiz 一致, 拒绝跟账号系统耦合, 等正式账号体系后再说 |
| **5.4** | "chunky-style 同事记仇" 边界 | **加 Forget mechanism** | Settings 页 "清空我对某 AI 同事的记忆 / 清空全部" + 调研 onboarding 透明展示 "AI 知道你什么" — 否则法务 / 隐私调研会打回 |
| **5.5** | event 写入颗粒度 | **混合(每轮 1 summary + 关键事件单独)** | 同时覆盖"宽 recall context"和"窄 recall 精确命中"两种 query 模式 |
| **5.6** | embedding 失败的 fallback | **embedding=NULL + recall 走 LIKE 全文检索** | 不能因 API 抖动丢史; LIKE recall 精度低但好过 0 |
| **5.7** | reflection LLM 选型 | **主 model (M2 / claude-opus-4-7) + events 集合 hash 缓存** | 1 局 ~30 events 单次 reflection ~2K tok, 同样 events 集合 hash 命中率高 |

### 5.2 详细 — Minimax embedding 下架的三重证据

> 2026-05-22 实测:

1. **dashboard quota** — 用户截图展示 11 个 quota line(文本生成 4500 / TTS HD 11000 / 视频生成 2+2 / 音乐生成 4+100 / 音乐翻唱 100 / 歌词 100 / 图像 120 / 图片理解 450 / 网络搜索 450), **embedding 不在其中**
2. **直营 sk-api- key 实测** — 在 `api.minimaxi.com` 和 `api.minimax.chat` 两个 region, model 名 `embo-01` / `embo-01-v2` / `MiniMax-Embedding` / `minimax-embedding` / `text-embedding-v1` 全部返回 `status_code: 1008, status_msg: insufficient balance`(同一错误码 ⇒ gating 不在 model 层而在产品线层)
3. **官方文档 `/docs/guides/models-intro`** — 列出 text / speech / video / image / music 五大类, **没有 embedding 类目**

⇒ 不再纠结充值,直接切 OpenAI 路径。Minimax 现有 sk-cp- 套餐继续 cover chat / TTS / image, 不动。

## 6. 风险 + 对冲

| 风险 | 概率 | 影响 | 对冲 |
|---|---|---|---|
| pgvector recall 性能 — HNSW 索引在 10w+ entries 后变慢 | 中 | 用户感知卡顿 | 加 `target_user_id` 复合索引;>50w entries 自动 archive 老旧 entries 到冷表 |
| Qingyun OpenAI 中转限流 / 抖动 | 中 | reflection 触发集中可能 burst; 中转链路偶发 5xx | LRU cache(content-hash 去重)+ 单进程队列限流; 失败走 §5.6 NULL embedding + LIKE fallback,不丢史 |
| memory 隐私问题(用户感到被监视) | 中 | 调研负面反馈 | (5.4) Forget mechanism + Settings 页透明展示"AI 知道你什么" |
| 跨局记仇变成"AI 永远讨厌新人" — 第一次玩的 player 接收到老用户的 baseline | 中 | NPS ↓ | reflection prompt 加 "对新见到的人请保留 fresh judgement" 软约束 |
| pgvector 部署增加运维复杂度 | 高 | 中文社区 deploy 文档少 | Neon 托管 → 0 运维; 本地 docker-compose 一键起 |

## 7. 不在本 RFC 范围

- **多模态 memory** (图片 / 语音作为 memory) — v6.x+
- **Memory 跨 archetype 共享** (sass-master 知道 social-cat 的 belief) — Phase D 后再考虑
- **GDPR 完整合规** (用户导出 / 删除流程) — v1.0 公开商业化前补
- **Memory 跨用户共享** ("听说 X 玩家很坑") — 隐私雷区, 长期不做
- **回切 Minimax embedding** — 2026-05-22 实测确认 Minimax 已下架,该路径**永久关闭**,
  除非 Minimax 重启 embedding 产品线(届时需要重新立项,新立 RFC)
